# PARKSIDE 웹 개발 안내

관련 Issue: #4 웹 기본 화면, #6 편집기, #8 수동 주행. PARKSIDE는 디자인용 임시 이름입니다. 이 변경만으로 세 Issue 전체가 완료되는 것은 아닙니다.

## 지금 실행되는 것

- 고정 환경 3개 선택: 넓은 직각 주차, 옆 차량, 기둥. 차량은 개발용 컴팩트 1종입니다.
- 차콜/실버의 시네마틱 랜딩 → 같은 3D 공간으로 카메라 진입 → 차고 선택·주행 → 실제 결과·재도전.
- 곡선 프로파일 차량, 자체 생성 반사 조명·아스팔트 질감, 옥상 데크와 외곽 스카이라인. 외부 에셋은 없습니다.
- Three.js 차량 추적/탑뷰/후방/자유 시점, 격자·센서 표시. 자유 시점은 드래그 회전이 가능합니다.
- 팀원의 `ParkingEngine`으로 계산하는 직접 운전, 실제 차체 충돌·주차 성공·90초 timeout 결과.
- P/R/D 기어(단축키 P/Q/E), W 액셀·S 브레이크·A/D 조향(방향키도 동일), 좌우 드래그 핸들과 길게 누르는 터치 페달. Space 일시정지, 창 이탈·가이드 열기 자동 일시정지.
- 방향별 광선 차체 여유·원시 센서값·실측 기반 경고음(사용자가 켜야 재생), 실제 제동/기어 입력에 연결된 브레이크등·후진등.
- R 전환 시 추적 카메라를 후방 시점으로 변경하고 현재 조향 연장선을 표시합니다. 탑뷰/자유 시점은 자동으로 바꾸지 않습니다.
- 실제 ray-box 센서 36개의 거리 시각화. 무잡음이며 위치는 시뮬레이션의 이상적인 자기 위치입니다.
- 초기 정적 리소스 실패/8초 timeout/재시도/취소, 모바일 레이아웃, 키보드 선택·포커스 복귀.

**아직 없는 것:** 자유 장애물 편집·차종 선택·학습 모델·Episode 저장/내보내기·재생·공유·업로드·공개 배포. 마스코트는 준비 중 안내만 보여주고 시작 버튼을 비활성화합니다. 가짜 관전 결과는 만들지 않습니다. 엔진의 기준 제어기 역시 학습 정책이 아닙니다.

## 실행과 검사

저장소 루트에서 Node.js 22.12 이상으로 실행합니다.

```bash
npm --prefix web ci
npm --prefix web run dev
```

기본 주소는 `http://127.0.0.1:5173`입니다. 앱 실행 자체에는 engine 개발 의존성 설치가 필요하지 않습니다. 엔진 검사에는 별도 설치가 필요합니다.

```bash
npm --prefix engine ci
npm --prefix engine run typecheck
npm --prefix engine test
npm --prefix web run build
cd web
npx playwright install chromium
npm test
```

Playwright는 Chromium으로 랜딩/환경 선택, P 고정·D/R·이동 중 변속 거부, 브레이크/키 해제, 일시정지/창 이탈, 준비 중 모델, 실패/취소/timeout, 실제 충돌, WebGL 실패 중단, 두 탭 독립, 모바일 노출과 모션 감소 설정을 검사합니다. 추가로 드래그·기어 단축키·CDP 두 손가락 터치 입력을 검사합니다. 경고음 테스트는 AudioContext를 계측 대역으로 바꿔 실제 센서 접근 중 발생한 음원 예약/해제/정지를 검사하며, 스피커의 실제 음량·청취 품질까지 확인한 것은 아닙니다. 별도 `driver-controls.spec.ts`와 `sensor-feedback.spec.ts`는 입력 변환·센서 결측/미검출·원시 거리/차체 여유·조향 연장선을 검증합니다. 모바일 폭/터치 에뮬레이션은 실제 iOS Safari 검증을 대신하지 않습니다. 스크린샷과 실패 trace는 `web/test-results/`에 생성되며 Git에는 넣지 않습니다.

## 엔진과 화면의 계약

- 엔진은 `engine/src/index.ts`에서 직접 가져옵니다. 별도 서버, WebSocket, 두 번째 물리 구현을 만들지 않습니다.
- world는 x-y 평면, z 위쪽입니다. Three.js에서는 `(x, 높이, -y)`로 표시합니다. 차량 pose는 뒷차축이므로 컴팩트 차체 중심은 진행 방향으로 1.3m 이동시킵니다.
- `FIXED_DT_S = 0.05`를 사용합니다. rAF는 누적기를 깨우며 실제 시간은 엔진의 simTimeS입니다. 긴 프레임의 따라잡기는 프레임당 0.15초로 제한하므로 느린 기기에서 벽시계보다 느리게 진행될 수 있습니다.
- 실행 시작 시 `structuredClone(scenario)`로 reset합니다. 실행 중 환경 변경은 막습니다. 키 해제·pointercancel·포커스 이탈·unmount에서 입력을 정리합니다. 일시정지는 시뮬레이션 시간을 멈추는 기능이지 실제 차량 제동 모델이 아닙니다.
- 가장 가까운 감지점의 원시값은 **차량 중심 센서의 거리**입니다. HUD의 광선 차체 여유는 해당 ray의 원시 거리에서 ray가 차량 직사각형을 빠져나오는 길이를 뺀 파생값입니다. 최근접 유클리드 거리나 실제 범퍼 초음파 센서가 아닙니다. 현재 센서는 장애물 박스를 감지하고, world bounds 충돌은 별도로 판단합니다. 장식 나무·표지·스카이라인·외곽 시설·스토퍼는 센서/충돌 장애물이 아닙니다.
- 주차 차량과 기둥은 `Scenario.obstacles`에서 직접 렌더링합니다. 주차선·데크는 아직 프리셋 전용 장식입니다. #6 자유 편집에서는 목표/경계까지 Scenario에서 생성하고, 임의 JSON을 현재 제한적인 엔진 검증에 바로 통과시키지 말고 양수 제원·크기/개수·겹침·경계 검증부터 추가해야 합니다.
- `runtime.json`은 정적 배포 리소스 확인용이며 주행 데이터나 정책을 반환하지 않습니다. 관전은 준비 화면일 뿐입니다. #11 정책 연결 시 같은 observation/command/step 경로를 사용하고 `controller_kind`와 정책 버전을 표시하세요.

## 디자인 원칙

2026-09-16 추가 사용자 피드백에 따라 **차량과 공간이 주인공인 시네마틱 경험**으로 변경했습니다. 파스텔/스티커 중심 디자인 대신 차콜·실버·낮은 채도의 센서 포인트, 큰 타이포, 전체 화면 주차장과 반사 조명을 사용합니다. [Polestar 4](https://www.polestar.com/kr/polestar-4-models/polestar-4-coupe/)의 차량 중심 구도·절제된 정보 배치와 사용자가 요청한 영화 타이틀 감각을 참고했습니다. 원본 사진·영상·차량 모델·상표를 복제하지 않았으며 현재 차량은 자체 코드로 만든 개발용 모델입니다. 실사 영상/고정밀 자동차 렌더링이 아닙니다.

참고한 공개 레퍼런스는 [Google Interland](https://beinternetawesome.withgoogle.com/en_us/interland)의 색과 입체 세계, [Slow Roads](https://slowroads.io/)의 차량/공간과 최소 주행 UI, [Bruno Simon](https://bruno-simon.com/)의 조작하며 탐색하는 경험, [주차의 달인 4](https://play.google.com/store/apps/details?hl=ko&id=com.ansangha.drparking4)의 주차 플레이 구성입니다. 소스 코드·에셋·브랜드를 가져오지 않았으며 레이아웃 복제나 제휴를 뜻하지 않습니다.

모션은 CSS와 기존 R3F만 사용하며 별도 라이브러리는 추가하지 않았습니다. 최초 진입에 1.8초 로고 페이드와 카메라 접근을 표시합니다. 로고는 입력을 막지 않으며 운전 시작 시 즉시 제거됩니다. 랜딩/주행은 **하나의 Canvas 인스턴스**를 공유합니다. 영역 크기와 카메라만 전환하며 초기 리소스 확인과 1.2초 진입 구간이 끝나기 전에는 엔진 실행·기어·페달 입력을 열지 않습니다. 재도전에는 최소 연출 대기를 추가하지 않습니다. 취소/오류는 이전 시작 요청을 무효화합니다. `tests/cinema.spec.ts`에서 Canvas identity 유지·준비 중 입력 차단·포커스·모션 감소를 검사합니다.

계기판 진입은 240ms이며 기어/페달 반응과 센서 수치에는 장식 모션을 추가하지 않습니다. 카메라는 frame delta 기반 감쇠로 추적/전환하며 물리 step과 분리합니다. `prefers-reduced-motion` 또는 장식 모션 중단은 카메라/장식 전환을 생략합니다. 실제 차량 이동은 꺼지지 않습니다. 가짜 주행/센서 스캔·스크롤 가로채기·자동 음악 재생은 넣지 않습니다. 실제 모바일 기기에서 GPU 성능과 장시간 세션 검증은 여전히 필요합니다.

결과는 실제 종료 사유·시간·D/R 방향 전환 횟수·최종 위치 오차입니다. 랜덤 점수/가짜 리더보드/참여 수를 만들지 않습니다. 재도전은 같은 프리셋을 reset하며 서로 다른 맵을 같은 실험으로 비교하지 않습니다.

3D와 마스코트는 코드 기반 도형/CSS로 만들었습니다. 외부 이미지·모델·폰트를 다운로드하지 않습니다. 아이콘은 lucide-react이며 Three.js 계열 의존성의 라이선스는 프로젝트 자체 라이선스와 별도로 관리해야 합니다. 상업 차량명·브랜드를 제원 검증 없이 붙이지 않습니다.

접근성은 native radio와 dialog, 텍스트 라벨, 포커스 복귀, 감소된 모션 설정을 기본으로 합니다. 미세한 설명 글자와 화면 대비는 실사용자 테스트에서 계속 개선할 항목입니다. 차량 주변 안전 판단을 실제 운전에 사용할 수 있다고 표현하지 않습니다.

## 배포와 남은 검증

사용자 결정에 따라 공개 배포는 당장 진행하지 않고 로컬 개발을 먼저 합니다. #4의 공개 preview 완료 조건은 남겨둡니다.

`npm --prefix web run build` 결과인 `web/dist/`는 정적 호스팅용입니다. `.github/workflows/web.yml`은 엔진/웹을 검사하고 `parking-web-preview` artifact를 올립니다. **artifact 업로드는 공개 배포가 아닙니다.**

호스팅 프로젝트를 생성할 때 저장소 루트를 기준으로 설치 `npm --prefix web ci`, 빌드 `npm --prefix web run build`, 출력 폴더 `web/dist`를 지정하세요. `web`만 복사하면 형제 폴더인 `engine` import가 깨집니다. 서버 Secret이나 DB 설정은 이 버전에서 필요하지 않습니다. GitHub Pages를 사용할 경우 소유자가 Pages 설정과 배포 워크플로를 별도로 활성화해야 합니다.

Three.js 계열 chunk가 크다는 Vite 경고가 있습니다. 로컬 빌드는 통과하지만 실제 모바일 네트워크 초기 로딩 시간은 아직 측정하지 않았습니다. 공개 URL에서 새로고침·runtime.json·3D chunk 경로, 실기기 WebGL/Safari·터치, 장시간 세션을 추가 확인한 뒤 #4의 공개 preview 완료 조건을 닫습니다.

## 수동 조작의 범위와 한계

- P에서는 가속하지 않습니다. D/R의 부호는 기어가 결정하며 S/아래 방향키는 후진이 아니라 브레이크입니다. 기어 변경은 속도 절대값이 0.001m/s 이하일 때만 허용합니다.
- 현재 페달은 0/1 입력입니다. 액셀 0.8m/s², 브레이크 2m/s², 무입력 감속 0.25m/s²를 목표 속도 변화로 변환하고 엔진의 속도/변화율 한계를 다시 적용합니다. 브레이크가 액셀보다 우선하며 0을 지나 반대 방향으로 가속하지 않습니다. 크리프·경사·실제 변속기·타이어 모델은 없습니다.
- 조향 입력은 0.75rad/s로 누적하고 놓으면 0.45rad/s로 중앙 복원합니다. 이는 키보드용 보조이며 실제 조향 복원력 모델이 아닙니다. HUD 핸들은 시각적 비율 10:1로 회전하고 앞바퀴는 실제 엔진 조향각을 표시합니다.
- 드래그는 시작 조향값에서 수평 85px당 정규화 조향 축 1만큼 변환하고 [-1,1]로 제한합니다. 엔진의 동일 조향 변화율/각도 제한을 통과합니다. 손을 떼거나 pointercancel·blur·pause가 발생하면 입력을 해제합니다. 페달을 다른 손으로 누르는 도중 발생하는 DOM focus 이동은 드래그를 취소하지 않습니다.
- 후진 연장선은 기존 `integrateBicycleModel`로 현재 조향을 고정해 3.2m 연장한 좌우 뒷범퍼 궤적입니다. 실제 속도/향후 입력·충돌·주차 가능성을 예측하는 계획기가 아닙니다.
- 엔진의 주차 성공 조건은 그대로 유지합니다. 엔진이 success로 정지한 뒤 P 선택을 요구하는 것은 **UI 마무리 단계**이며 정책 평가에 P 요구를 추가한 것이 아닙니다. 방향 전환 횟수는 D↔R 선택 변경이며 실제 이동 방향 변경 횟수와 구분합니다. P를 거쳐도 이전 주행 기어를 기억합니다.
- 미래 기록 기능에서는 기어/페달 원시 입력, 요청/적용 command, 시점/센서 도움 사용을 함께 보존해야 합니다. 현재 HUD와 결과가 Episode 저장을 대신하지는 않습니다.

## 센서 피드백과 소리

- 전방/좌측/후방/우측 4개 각도 구역에서 감지 ray의 파생 차체 여유 최솟값을 표시합니다. 읽은 센서 원시값은 수정하지 않으며 정책 입력에도 이 UI 파생값을 추가하지 않습니다.
- max range는 `미검출`, 유효 ray가 없거나 갱신 시각이 비정상/2주기보다 오래되면 `수신 없음`입니다. 미검출/결측을 안전 또는 0m로 표시하지 않습니다. 멈춘 화면은 `HOLD`로 표시하며 시뮬레이션 시각 기준으로 신선도를 계산합니다.
- 음소거가 기본입니다. 사용자가 센서 패널의 소리 버튼을 켠 뒤 활성 주행에서만 Web Audio 음원을 만듭니다. 파생 여유 1.5m 이내 750ms, 0.8m 이내 350ms, 0.35m 이내 180ms 간격입니다. 임계값은 게임 UI 설정이지 실제 차량의 안전 기준이 아닙니다.
- pause·창 이탈·종료·음소거에서 타이머/음원을 해제하고 화면 이탈 시 AudioContext를 닫습니다. 오디오 미지원/실패는 안내하고 시각 경고를 계속 제공합니다. 자동 제동은 없습니다.
- 36개 이산 ray 사이의 작은 물체, 경계/장식 등은 놓칠 수 있습니다. 센서 경고가 없어도 차체 충돌은 발생할 수 있습니다. 센서 시뮬레이션만으로 학습된 Physical AI를 구현했다고 주장하지 않습니다.
