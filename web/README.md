# Mr.Park 미스터팍 웹 개발 안내

관련 Issue: #6 편집기, #10 기록, #12 마스코트, #14 비교, #13 공유와 기여 준비. 서비스와 AI 마스코트의 이름은 모두 **Mr.Park**, 한국어 표기는 **미스터팍**입니다. #4/#8의 남은 공개 환경 검증은 #15로 이관했습니다.

화면·브라우저 제목·안내 페이지와 다운로드 파일 이름에는 새 브랜드를 사용합니다. 기존 맵/기록을 그대로 읽도록 `parkside-map.v1`, `parkside-episode.v1`, Scenario ID와 브라우저 저장 키는 유지합니다. 내보내기 파일은 `mr-park-map.json`과 `mr-park-episode-<id>.json`이며 JSON 형식은 바뀌지 않습니다. 배포 주소와 리소스 이름 유지 이유는 [배포 안내](../docs/cloudflare-deployment.md#서비스명과-기존-식별자)를 참고하세요.

## 지금 실행되는 것

- 기본 환경 3개 선택과 탑뷰 맵 편집: 넓은 직각 주차, 옆 차량, 기둥. 차량은 개발용 컴팩트 1종입니다.
- 차콜/실버의 시네마틱 랜딩 → 같은 3D 공간으로 카메라 진입 → 차고 선택·주행 → 실제 결과·재도전.
- 고화질은 CC BY 4.0 Car Concept 차량, 성능 우선/파일 실패는 자체 경량 차체를 사용합니다. 외곽 차고·반사 조명·마스코트는 코드로 구성합니다. [에셋 출처](public/models/NOTICE.md)를 확인하세요.
- Three.js 차량 추적/탑뷰/후방/자유/운전석 시점, 격자·센서 표시. 후방 카메라와 좌우 반전 미러는 같은 WebGL context에서 실제 장면을 다시 렌더합니다.
- 팀원의 `ParkingEngine`으로 계산하는 직접 운전, 실제 차체 충돌·주차 성공·90초 timeout 결과.
- 주차칸과 일치하는 판정 영역, 차체·위치·각도·정지 조건 안내, 실제 1초 정지 확인과 P 마무리 화면. 시간 초과는 마지막 미충족 이유를 표시합니다.
- P/R/D 기어(단축키 P/Q/E), D ↑ 액셀·↓ 브레이크 / R ↓ 액셀·↑ 브레이크, W 액셀·S 브레이크는 고정, A/D 또는 ←/→ 조향. 좌우 드래그 핸들과 길게 누르는 터치 페달. Space 일시정지, 창 이탈·가이드 열기 자동 일시정지.
- 약 6.8초 기술 필름: 차체 근접 → 실제 센서 기록 → 기준 경로 → 차량 전경. 카메라·빛·타이포 연출은 학습 정책·사용자 기록과 분리하며 언제든 건너뛸 수 있습니다.
- 첫 직접 운전의 3단계 안내, 3D 주차장 작업대와 정밀 평면 편집, 차체·센서·조향을 살펴보는 별도 기술 설명 뷰.
- 미스터팍의 걷기·문 열기·탑승 연출 후 실제 정책 실행. 고화질 차량에 문/탑승자 표시를 제공하며 성능 우선은 외부 캐릭터 접근 연출만 제공합니다. 탑승은 학습된 로봇 행동이 아닙니다.
- 방향별 광선 차체 여유·원시 센서값·실측 기반 경고음(사용자가 켜야 재생), 실제 제동/기어 입력에 연결된 브레이크등·후진등.
- P/D/R 변속은 사용자가 선택한 카메라 시점을 바꾸지 않습니다. 후방 시점은 버튼으로 직접 선택하며 R에서는 현재 조향 연장선과 후진등을 표시합니다. 센서 패널도 기존 상태를 유지합니다.
- 실제 ray-box 센서 36개의 거리 시각화. 무잡음이며 위치는 시뮬레이션의 이상적인 자기 위치입니다.
- 초기 정적 리소스 실패/8초 timeout/재시도/취소, 모바일 레이아웃, 키보드 선택·포커스 복귀.

**구현한 것:** 맵 편집·로컬 Episode·상태 재생과 [실제 마스코트 추론](../docs/mascot.md), Cloudflare 공개 배포·선택형 비공개 R2 수집/삭제를 제공합니다. 수집은 기본 OFF이며 처음 선택 후 다음 완료 주행부터 자동 전송합니다. 단독 Vite 서버는 수집 API가 없어 자동으로 비활성입니다. [수집과 학습 안내](../docs/collection.md)를 참고하세요. **아직 없는 것:** 차종 선택·사용자 데이터로 검증된 모델 개선·자동 모델 교체. 모델은 초기 실험 단계이며 heldout 성공 0/1입니다. 엔진의 기준 제어기와 오프닝 재생은 학습 정책이 아닙니다.

## 실행과 검사

저장소 루트에서 Node.js 22.12 이상으로 실행합니다.

```bash
npm --prefix web ci
npm --prefix web run dev
```

기본 주소는 `http://127.0.0.1:5173`입니다. 앱 실행 자체에는 engine 개발 의존성 설치가 필요하지 않습니다. 엔진 검사에는 별도 설치가 필요합니다.

```bash
npm --prefix engine ci
npm --prefix engine run typecheck
npm --prefix engine test
npm --prefix web run build
cd web
npx playwright install chromium
npm test
```

Playwright는 Chromium으로 랜딩/환경 선택, P 고정·D/R·이동 중 변속 거부, 브레이크/키 해제, 일시정지/창 이탈, 실제 모델 추론, 실패/취소/timeout, 실제 충돌, WebGL 실패 중단, 두 탭 독립, 모바일 노출과 모션 감소 설정을 검사합니다. 추가로 드래그·기어 단축키·CDP 두 손가락 터치 입력을 검사합니다. 경고음 테스트는 AudioContext를 계측 대역으로 바꿔 실제 센서 접근 중 발생한 음원 예약/해제/정지를 검사하며, 스피커의 실제 음량·청취 품질까지 확인한 것은 아닙니다. 별도 `driver-controls.spec.ts`와 `sensor-feedback.spec.ts`는 입력 변환·센서 결측/미검출·원시 거리/차체 여유·조향 연장선을 검증합니다. 모바일 폭/터치 에뮬레이션은 실제 iOS Safari 검증을 대신하지 않습니다. 스크린샷과 실패 trace는 `web/test-results/`에 생성되며 Git에는 넣지 않습니다.

추가 검사: `mascot.spec.ts` 실제 가중치·지원 규격·tensor 해제/수동 입력 차단, `compare.spec.ts` 동일 조건·실패 포함 지표, `share-link.spec.ts` 맵 최소 필드 링크·적용, `contribution.spec.ts` 개발용 동의 UI입니다. `npm --prefix web run test:local-api`는 별도의 실제 loopback HTTP 테스트이며 [실제 사용자 업로드가 아닌 합성 테스트](../server/README.md)만 허용합니다.

## 엔진과 화면의 계약

- 엔진은 `engine/src/index.ts`에서 직접 가져옵니다. 별도 서버, WebSocket, 두 번째 물리 구현을 만들지 않습니다.
- world는 x-y 평면, z 위쪽입니다. Three.js에서는 `(x, 높이, -y)`로 표시합니다. 차량 pose는 뒷차축이므로 컴팩트 차체 중심은 진행 방향으로 1.3m 이동시킵니다.
- `FIXED_DT_S = 0.05`를 사용합니다. rAF는 누적기를 깨우며 실제 시간은 엔진의 simTimeS입니다. 긴 프레임의 따라잡기는 프레임당 0.15초로 제한하므로 느린 기기에서 벽시계보다 느리게 진행될 수 있습니다.
- 차량/앞바퀴/추적 카메라는 이전·현재 tick 사이를 표시 전용으로 보간합니다. 최대 한 tick(50ms)의 시각 지연이 있으며 외삽하지 않습니다. 센서/HUD/충돌/평가에는 원본 step 결과를 사용합니다. pause·종료·reset은 최신 원본 위치로 맞추고, 정적 주차장 트리와 차량 형상은 재사용합니다. 60fps나 실기기 성능을 보장하는 것은 아닙니다.
- 실행 시작 시 `structuredClone(scenario)`로 reset합니다. 실행 중 환경 변경은 막습니다. 키 해제·pointercancel·포커스 이탈·unmount에서 입력을 정리합니다. 일시정지는 시뮬레이션 시간을 멈추는 기능이지 실제 차량 제동 모델이 아닙니다.
- 가장 가까운 감지점의 원시값은 **차량 중심 센서의 거리**입니다. HUD의 광선 차체 여유는 해당 ray의 원시 거리에서 ray가 차량 직사각형을 빠져나오는 길이를 뺀 파생값입니다. 최근접 유클리드 거리나 실제 범퍼 초음파 센서가 아닙니다. 현재 센서는 장애물 박스를 감지하고, world bounds 충돌은 별도로 판단합니다. 장식 나무·표지·스카이라인·외곽 시설·스토퍼는 센서/충돌 장애물이 아닙니다.
- 주차 차량과 기둥은 `Scenario.obstacles`에서 직접 렌더링합니다. 목표칸의 채움·외곽선·화살표는 `goalSpace`에서 생성하며 선의 중심이 판정 경계입니다. 나머지 주차선·데크는 프리셋 전용 장식입니다. #6 자유 편집에서는 경계까지 Scenario에서 생성하고, 임의 JSON을 현재 제한적인 엔진 검증에 바로 통과시키지 말고 양수 제원·크기/개수·겹침·경계 검증부터 추가해야 합니다.
- `runtime.json`은 정적 배포 리소스 확인용이며 주행 데이터나 정책을 반환하지 않습니다. 학습 관전은 같은 observation/command/step 경로에서 별도 고정 모델을 실행하며 `controllerKind=learned`와 정책 체크섬을 기록합니다. [마스코트 경계](../docs/mascot.md)를 따릅니다.

## 디자인 원칙

2026-09-19 사용자 피드백에 따라 **차량과 공간이 주인공인 시네마틱 경험**을 하단까지 확장했습니다. 블루 조명·실버·앰버 신호선, 큰 타이포, 전체 화면 주차장과 반사 조명을 사용합니다. ### 섹션 모션과 리소스 준비

- 운영 Static Assets의 전체 파일 응답에서도 WebKit이 영상 앞뒤를 탐색할 수 있도록, 배경 필름은 보일 때 한 번 다운로드한 Blob URL로 사용합니다. 다운로드 중에는 포스터를 유지하고 unmount 시 요청을 취소하고 URL을 해제합니다. 동작 줄이기에서는 다운로드하지 않습니다.
- 첫 운전 안내는 기어·센서·후진을 3개의 시각 카드로 설명합니다. 다음/닫기와 실제 기어 선택으로 진행하며, 주행을 시작하면 1초 뒤 사라집니다. 닫은 선택은 로컬에 기억하고 상단 조작 가이드에서 다시 열 수 있습니다. 설명 단계만 220ms 전환하며 실제 입력·센서 수치에는 장식 지연을 넣지 않습니다. 모달 안내의 표면·문자 색상을 함께 지정해 밝은 박스와 밝은 글씨가 겹치지 않게 합니다.

- `ScrollFilmBackdrop.tsx`는 랜딩 전체에 하나의 고정 영상 배경을 놓습니다. 스크롤 위치에 따라 카메라가 차량 주변을 이동하는 약 5초 필름의 시간을 앞뒤로 탐색합니다. 섹션은 투명하게 연결하고 구분선은 유지합니다. [ThreeUI](https://threeui.com/browse)는 타이포·버튼의 시각적 참고이며 패키지·소스·셰이더를 복사하지 않았습니다. 배경은 **AI 생성 브랜드 장식**이지 실제 센서/학습 데이터가 아닙니다.
- 카드 추적은 마우스+hover 장치에서만 requestAnimationFrame당 한 번 적용하며, 주행 진입·장식 모션 중단에서 해제합니다. 입력 버튼은 클릭 위치를 옮기지 않고 하이라이트·그림자·아이콘으로 반응합니다. 센서 수치·기어·페달의 시간 계약은 그대로입니다.
- 화면 밖 신호 그래픽과 숨은 탭의 장식을 중단합니다. 모션 감소에서는 타이포·배경·마퀴·카드 회전을 생략하고 모든 내용과 조작을 유지합니다. SVG 장식은 접근성 트리와 포인터 입력에서 제외합니다. 스크롤을 가로채지 않습니다.
- 고화질은 모듈/GLB 준비 중 전용 준비 화면을 표시하고, 차량이 준비된 이후 오프닝을 시작합니다. 로딩 중 경량 차를 먼저 보여주지 않습니다. 불확실한 퍼센트는 표시하지 않으며, 느린 연결에서는 **가볍게 시작하기**로 성능 우선을 직접 선택할 수 있습니다. 이미 진행 중인 GLB 요청은 브라우저 캐시에 남을 수 있습니다.
- GLB 실패가 확정된 경우에는 경량 차로 복구합니다. 성능 우선을 처음부터 선택한 경우 GLB를 요청하지 않습니다. 별도 모션 라이브러리나 WebGL 배경 Canvas를 추가하지 않았습니다.
- `tests/motion-polish.spec.ts`는 지연 GLB/경량 전환, 포인터·키보드 선택, 모션 중단, 390/1440px 하단·편집·동의 기본값을 검사합니다. 모바일 실기기 GPU 성능 검증을 대신하지 않습니다.

참고한 공개 레퍼런스는 [Google Interland](https://beinternetawesome.withgoogle.com/en_us/interland)의 색과 입체 세계, [Slow Roads](https://slowroads.io/)의 차량/공간과 최소 주행 UI, [Bruno Simon](https://bruno-simon.com/)의 조작하며 탐색하는 경험, [주차의 달인 4](https://play.google.com/store/apps/details?hl=ko&id=com.ansangha.drparking4)의 주차 플레이 구성입니다. 소스 코드·에셋·브랜드를 가져오지 않았으며 레이아웃 복제나 제휴를 뜻하지 않습니다.

모션은 CSS·브라우저 video와 기존 R3F를 사용하며 별도 라이브러리는 추가하지 않았습니다. 최초 진입에 0.9초 로고 페이드와 카메라 접근을 표시합니다. 로고는 입력을 막지 않으며 종료 후 DOM에서 제거합니다. 랜딩/주행은 **하나의 전체 화면 WebGL Canvas 인스턴스**를 공유합니다. 운전 시작 시 현재 카메라 위치에서 차량 추적 시점으로 이동합니다. 320ms 동안 랜딩 정보를 먼저 지우고, 초기 리소스 확인과 최소 1.7초 진입 구간이 끝나면 엔진 실행·기어·페달 입력을 엽니다. 직접 운전 재도전에는 최소 연출 대기가 없고, 미스터팍은 모션 사용 시 4.2초 탑승 구간을 둡니다. 취소/오류는 이전 시작 요청을 무효화합니다. `tests/cinema.spec.ts`에서 Canvas identity·화면 크기 유지·준비 중 입력 차단·포커스·모션 감소를 검사합니다.

계기판 진입은 650ms이며 기어/페달 반응과 센서 수치에는 장식 모션을 추가하지 않습니다. 카메라는 frame delta 기반 감쇠로 추적/전환하며 물리 step과 분리합니다. `prefers-reduced-motion` 또는 장식 모션 중단은 카메라/장식 전환을 생략합니다. 실제 차량 이동은 꺼지지 않습니다. 가짜 주행/센서 스캔·스크롤 가로채기·자동 음악 재생은 넣지 않습니다. 실제 모바일 기기에서 GPU 성능과 장시간 세션 검증은 여전히 필요합니다.

결과는 실제 종료 사유·시간·D/R 방향 전환 횟수·최종 위치 오차입니다. 랜덤 점수/가짜 리더보드/참여 수를 만들지 않습니다. 재도전은 같은 프리셋을 reset하며 서로 다른 맵을 같은 실험으로 비교하지 않습니다.

고화질 차량은 Eric Chadwick / © 2024 Darmstadt Graphics Group의 Car Concept(CC BY 4.0, 약 11.2 MB)입니다. 원본 GLB는 보존하고 런타임에서 차축 2.6m·차체 4.4 × 1.8m에 맞춘 표시 좌표·재질·문 힌지를 적용합니다. 실제 차종의 제원/동역학 검증이 아닙니다. 원본 상표/번호판 표시를 제거합니다. 출처와 변경 내역은 `public/models/NOTICE.md`, 사용자용 `/credits.html`에 제공합니다. 성능 우선은 GLB를 요청하지 않습니다. 마스코트는 자체 도형이고 `public/art/mrpark-concept.png`는 AI 생성 디자인 콘셉트로, 실제 주행 화면과 다르다고 표시합니다. 아이콘은 lucide-react입니다.

접근성은 native radio와 dialog, 텍스트 라벨, 포커스 복귀, 감소된 모션 설정을 기본으로 합니다. 미세한 설명 글자와 화면 대비는 실사용자 테스트에서 계속 개선할 항목입니다. 차량 주변 안전 판단을 실제 운전에 사용할 수 있다고 표현하지 않습니다.

### 자동 장면 전환

상단 3D Canvas는 랜딩에서 문서 기준 `absolute` 배치로 페이지와 함께 이동합니다. 스크롤 이벤트로 `fixed` 위치를 뒤늦게 갱신하지 않으므로 아래 소개 문장 뒤로 밝은 주차장이 순간 노출되지 않습니다. 운전 진입 때는 같은 Canvas를 유지한 채 `fixed` 화면으로 전환합니다. `tests/hero-scroll.spec.ts`가 390/1440px의 정방향·역방향 스크롤 직후 경계 일치와 차고에서 운전 진입을 검사합니다.

랜딩은 DRIVE → SPACE → SENSE의 세 장면을 자동으로 반복합니다. `src/story.ts`는 장면당 4.8초 느린 촬영과 3.2초 구도 이동, 총 24초의 표현 전용 타임라인입니다. 구도 보간 위에 연속적인 작은 카메라 드리프트를 더해 장면 유지 중에도 정지하지 않습니다. 루프 위치·속도는 연속이고 제목은 구도 이동 중간에 교체합니다. 마우스 위치·드래그·스크롤을 재생 시각에 연결하지 않습니다. 아래로 스크롤하면 평범하게 차고로 이동합니다. 화면 밖/숨은 탭에서는 재생을 멈추고, 운전 버튼은 장면 교체와 무관하게 같은 자리에 유지합니다. 느린 기기에서 큰 프레임 시간을 0.1초로 제한하므로 실제 재생은 더 느릴 수 있습니다.

SENSE는 엔진 reset 시 계산한 현재 배치의 가상 거리 광선과 원시 최소 거리입니다. 세 장면 소개 중에는 수동 운전 엔진의 물리 시간을 진행하지 않습니다. 실제 운전에 들어가면 기존 step 결과를 표시합니다. 생성 영상, 가짜 센서 탐지 로그, 학습된 정책을 사용하지 않습니다. 별도 영상 파일이나 모션 라이브러리 없이 기존 R3F/CSS로 렌더합니다.

첫 진입 기술 필름은 `src/opening.ts`에서 별도 `ParkingEngine`과 `baselineReverseParkController`로 계산한 실제 성공 기록을 약 6.8초로 압축 표시합니다. 물리 속도를 높이는 것이 아니라 기록 재생률과 카메라를 연출합니다. `OpeningTelemetry`의 거리선·경로는 그 기록의 실제 가상 ray-box 거리·뒷차축 좌표입니다. 원형 펄스·빛 스윕·타이포는 강조 연출이며 검출 결과가 아닙니다. 수동 HUD와 Episode에는 섞지 않습니다. 건너뛰기·직접 운전·다른 프리셋·모션 감소에서 생략하고 오디오/저장/업로드하지 않습니다. `tests/motion.spec.ts`, `tests/drive-motion.spec.ts`, `tests/art-direction.spec.ts`에서 기록·전환·축소 화면·실패 복구를 검증합니다.

## 기술 전시와 탑승 연출

- `BoardingRobot`의 걷기와 `DetailedCar`의 문 힌지는 4.2초짜리 표시 전용 타임라인입니다. 모델 준비와 연출 완료 후에만 기존 `driving.start()`를 호출합니다. 취소·오류는 시작을 무효화하며 모션 감소에서는 연출 대기를 생략합니다. 실제 정책은 관측만으로 추론하고 성공을 보장하지 않습니다.
- `SensorLab`은 화면에 보일 때만 설명용 Canvas를 만듭니다. 고정 데모 환경의 실제 reset 관측과 표시 전용 조향각을 사용하며 주행·학습하지 않습니다.
- 운전석/보조 카메라는 표시 지원입니다. 선택을 Episode 도움 메타데이터로 남기므로 센서 전용 학습 데이터와 무조건 섞지 않습니다. 첫 운전 안내 완료 여부만 로컬에 저장합니다.
- 고화질 차량은 경량 모델보다 GPU/다운로드 비용이 큽니다. 저사양·모바일에서는 성능 우선을 선택하고 실제 기기 프레임 검증 후 배포하세요. 포토리얼 영상이나 실차 안전 시뮬레이터라고 주장하지 않습니다.

`prefers-reduced-motion`과 장식 모션 중단에서는 카메라/장면 자동 전환 대신 정적인 소개를 제공합니다. 숨은 장면은 `inert`와 `aria-hidden`으로 키보드/스크린리더 탐색에서 제외합니다. 랜딩에서는 3D 드래그를 끄고 세로 스크롤을 허용하며, 운전의 orbit 모드에서만 카메라 회전이 가능합니다. `tests/cinema.spec.ts`는 루프 경계, 390/1440px 자동 진행·모션 중단, 스크롤 독립, Canvas 연속성과 모션 감소를 검사합니다.

## 배포와 남은 검증

사용자 결정에 따라 공개 배포는 하지 않습니다. 공개 URL·실기기·운영 점검은 #15에 남겨둡니다.

`npm --prefix web run build` 결과인 `web/dist/`는 정적 호스팅용입니다. `.github/workflows/web.yml`은 엔진/웹을 검사하고 `parking-web-preview` artifact를 올립니다. **artifact 업로드는 공개 배포가 아닙니다.**

호스팅 프로젝트를 생성할 때 저장소 루트를 기준으로 설치 `npm --prefix web ci`, 빌드 `npm --prefix web run build`, 출력 폴더 `web/dist`를 지정하세요. `web`만 복사하면 형제 `engine`, `training/src/features.ts`, `training/model` import가 깨집니다. 학습 패키지의 별도 npm 설치/재학습 없이 고정 모델을 번들링합니다. 실제 기여 수집이 꺼진 정적 웹은 서버 Secret이나 DB 설정이 필요하지 않습니다. `server/`는 개발용이며 공개 배포하지 않습니다. GitHub Pages를 사용할 경우 소유자가 Pages 설정과 배포 워크플로를 별도로 활성화해야 합니다.

Three.js 및 TensorFlow 정책 chunk가 크다는 Vite 경고가 있습니다. 정책은 선택할 때만 로딩하지만 실제 모바일 네트워크 초기 로딩 시간은 아직 측정하지 않았습니다. 공개 URL에서 새로고침·runtime.json·3D/정책 chunk·가중치 경로, 실기기 WebGL/Safari·터치, 장시간 세션을 추가 확인한 뒤 #15 공개 검증을 완료합니다.

## 수동 조작의 범위와 한계

- P에서는 가속하지 않습니다. D는 ↑ 액셀/↓ 제동, R은 ↓ 액셀/↑ 제동입니다. W 액셀/S 제동은 고정이며 방향키가 기어를 자동 변경하지 않습니다. 기어 변경은 속도 절대값이 0.001m/s 이하일 때만 허용합니다. 입력은 키 코드와 화면 페달별로 보존하므로 ↑와 W를 함께 누른 뒤 W만 떼어도 ↑ 액셀은 유지됩니다. 변속 시 입력을 지우고 키 반복 이벤트로 다시 켜지지 않게 합니다.
- 현재 페달은 0/1 입력입니다. 액셀 0.8m/s², 브레이크 2m/s², 무입력 감속 0.25m/s²를 목표 속도 변화로 변환하고 엔진의 속도/변화율 한계를 다시 적용합니다. 브레이크가 액셀보다 우선하며 0을 지나 반대 방향으로 가속하지 않습니다. 크리프·경사·실제 변속기·타이어 모델은 없습니다.
- 조향 입력은 0.75rad/s로 누적하고 놓으면 0.45rad/s로 중앙 복원합니다. 이는 키보드용 보조이며 실제 조향 복원력 모델이 아닙니다. HUD 핸들은 시각적 비율 10:1로 회전하고 앞바퀴는 실제 엔진 조향각을 표시합니다.
- 드래그는 시작 조향값에서 수평 85px당 정규화 조향 축 1만큼 변환하고 [-1,1]로 제한합니다. 엔진의 동일 조향 변화율/각도 제한을 통과합니다. 손을 떼거나 pointercancel·blur·pause가 발생하면 입력을 해제합니다. 페달을 다른 손으로 누르는 도중 발생하는 DOM focus 이동은 드래그를 취소하지 않습니다.
- 후진 연장선은 기존 `integrateBicycleModel`로 현재 조향을 고정해 3.2m 연장한 좌우 뒷범퍼 궤적입니다. 실제 속도/향후 입력·충돌·주차 가능성을 예측하는 계획기가 아닙니다.
- 동일 Scenario에 대한 엔진의 성공 규칙은 유지합니다. 엔진이 success로 정지한 뒤 P 선택을 요구하는 것은 **UI 마무리 단계**이며 정책 평가에 P 요구를 추가한 것이 아닙니다. 성공으로 종료된 엔진은 더 이상 움직이지 않으므로 마지막 적용 속도가 정지 허용값(0.05m/s) 이내라면 P 확인을 허용합니다. 주행 중 변속 기준(0.001m/s)은 그대로입니다. 방향 전환 횟수는 D↔R 선택 변경이며 실제 이동 방향 변경 횟수와 구분합니다. P를 거쳐도 이전 주행 기어를 기억합니다.
- 기록 기능은 기어/페달 원시 입력, 요청/적용 command, 시점/센서 도움 사용을 함께 보존합니다. HUD와 Episode의 구분은 [로컬 기록 계약](../docs/local-episodes.md)을 따릅니다.

## 주차 판정과 웹 연습 프리셋 v2

`parkside-<template>-v2`는 목표칸 5.4×2.8m, 중심 `(0, 1.6)`, 뒷차축 목표 `(0, 2.9, -π/2)`, 위치 허용 오차 0.6m입니다. 이전 웹 v1의 4.5m 칸/0.25m 위치 오차는 4.4m 차량에 지나치게 여유가 적었습니다. 차체 전체 포함, 약 5° 각도, 0.05m/s 이하 정지 1초 연속 유지, 충돌 우선과 90초 제한은 유지합니다. 위치 오차 이내라도 선 밖·장애물 접촉이면 성공이 아닙니다. 화살표는 차량 앞쪽 방향입니다.

`ParkingEngine.getParkingStatus()`에서 평가와 같은 조건 및 시뮬레이션 정지 유지 시간을 읽습니다. UI 호출이나 일시정지는 시간을 추가하지 않습니다. 이 정보는 truth 기반 운전 보조이며 정책 `Observation`에 추가하지 않습니다. 준비 상태는 성공 확정과 다르며 실제 `outcome.reason === "success"` 후에만 P 마무리를 표시합니다. 이미 P라면 바로 성공 결과를 표시합니다.

기존 `examples/scenarios`/학습 fixture의 기준은 바꾸지 않았습니다. v1/v2 기록은 같은 실험으로 비교하지 않으며 Episode에는 전체 Scenario snapshot과 버전을 보존합니다. `tests/parking-feedback.spec.ts`는 44cm 오차의 실제 성공, 영역 밖/반대 방향 거부, 회전한 목표선 좌표, 데스크톱/모바일 안내·P 확인·성공·timeout 결과를 검사합니다. 브라우저 성공 테스트만 시작점을 칸 안으로 옮기며 엔진/결과/타이머는 모의 구현하지 않습니다.

## 센서 피드백과 소리

- 전방/좌측/후방/우측 4개 각도 구역에서 감지 ray의 파생 차체 여유 최솟값을 표시합니다. 읽은 센서 원시값은 수정하지 않으며 정책 입력에도 이 UI 파생값을 추가하지 않습니다.
- max range는 `미검출`, 유효 ray가 없거나 갱신 시각이 비정상/2주기보다 오래되면 `수신 없음`입니다. 미검출/결측을 안전 또는 0m로 표시하지 않습니다. 멈춘 화면은 `HOLD`로 표시하며 시뮬레이션 시각 기준으로 신선도를 계산합니다.
- 음소거가 기본입니다. 사용자가 센서 패널의 소리 버튼을 켠 뒤 활성 주행에서만 Web Audio 음원을 만듭니다. 파생 여유 1.5m 이내 750ms, 0.8m 이내 350ms, 0.35m 이내 180ms 간격입니다. 임계값은 게임 UI 설정이지 실제 차량의 안전 기준이 아닙니다.
- pause·창 이탈·종료·음소거에서 타이머/음원을 해제하고 화면 이탈 시 AudioContext를 닫습니다. 오디오 미지원/실패는 안내하고 시각 경고를 계속 제공합니다. 자동 제동은 없습니다.
- 36개 이산 ray 사이의 작은 물체, 경계/장식 등은 놓칠 수 있습니다. 센서 경고가 없어도 차체 충돌은 발생할 수 있습니다. 센서 시뮬레이션만으로 학습된 Physical AI를 구현했다고 주장하지 않습니다.

# 성능·오류 복구

## 차고와 촬영 시야

- 차고의 `직접 운전하기` / `미스터팍에게 맡기기` 버튼은 모드 선택 없이 각각 사람/실제 정책 실행으로 바로 연결합니다. 재시작은 현재 모드를 유지합니다.
- 미스터팍이 충돌하거나 시간이 끝나면 `내가 운전해 볼게`로 같은 출발점에서 직접 도전할 수 있습니다. 성공 후 감사 메시지와 **해당 주행의** 전송 상태를 따로 표시합니다. 동의 없이도 연습 가능하며 과거 기록 소급 전송이나 즉시 학습은 없습니다. [참여 흐름](../docs/mascot.md#실패-후-함께-도전하기-13)을 참고하세요.
- 첫 운전 요청은 기록 선택 창을 먼저 엽니다. 선택 확정 전에는 실행하지 않으며 `기록 없이 시작`도 동일하게 제공합니다. 브라우저 보관과 학습 전송을 구분하고 수집 필드·30일 보관·학습 목적은 펼치지 않아도 보입니다. 선택은 안내 버전과 함께 기억하고 차고의 `기록 설정`에서 변경·서버 삭제가 가능합니다. 창 닫기/Escape는 초안을 적용하거나 운전을 시작하지 않습니다.
- 하단 `조작판 접기`는 페달·핸들 입력을 해제하고 속도·현재 기어·정지/종료·펼치기 버튼을 남깁니다. 키보드 운전은 유지되며 터치 조작은 다시 펼칩니다. 실제 차량·카메라·엔진 상태를 초기화하지 않습니다.
- 클릭 원형 파동·촘촘한 점군·격자와 섹션별 발광 배경을 제거했습니다. 버튼 중심에 따라 기존 영상 구도가 살짝 이동하고 1.1초 후 복귀합니다. 키보드 선택도 같은 버튼 중심을 사용하며 dialog/주행 입력에는 적용하지 않습니다.
- 영상은 하단이 보이고 모션을 허용할 때만 요청합니다. 스크롤을 가로채지 않으며 seek 완료를 기다려 다음 시간을 적용합니다. 정지/화면 밖/숨은 탭에서는 RAF를 유지하지 않습니다. 모션 감소에서는 처음부터 배경 MP4를 요청하지 않고 포스터를 표시하며, 실패도 포스터로 복구합니다. 주행 시 배경 전체가 제거되고 엔진·가상 센서·기록 계약은 바뀌지 않습니다.
- 소개 영상은 약 3.69초 루프, 배경은 별도로 생성·보정한 약 4.97초 카메라 이동 필름입니다. 무료 Wan 데모를 사용했고 Seedance/Runway나 실시간 생성 API는 사용하지 않습니다. 배경은 로컬 AI 2배 보정한 1664×960/32fps MP4 약 8.24MB이며 초기 화면에서는 지연 로드합니다. 생성·보정·라이선스 출처·설정은 [제작 기록](public/art/README.md)에 있습니다. 브라우저 native video를 사용하며 별도 npm 의존성을 추가하지 않았습니다.
- `#garage` / `#experiment`에서 새로고침하면 최상단 오프닝을 다시 재생합니다. 일반 차고·맵 공유 딥링크 진입 및 동작 줄이기 설정에서는 자동 오프닝을 생략합니다. 고화질 차량 로딩 중이나 비활성 탭에서는 재생 시간을 소비하지 않습니다. 오프닝 중 다른 섹션으로 이동하거나 아래로 스크롤하면 자막 연출을 종료합니다.
- 실제 운전 화면은 컷어웨이 뷰입니다. 추적/후방 카메라를 가리는 촬영용 천장 보·기둥·외벽은 숨깁니다. 시나리오 장애물·주차 차량과 엔진 충돌·센서 계산은 그대로이며, R 선택으로 추적 카메라를 반전시키지 않습니다.
- 바깥 연석의 **안쪽 면**은 `scenario.bounds`에서 직접 계산합니다. 기존의 X축 10cm·앞쪽 약 17.5cm 시각적 여유 오차를 제거했으며 비대칭 커스텀 맵에도 적용합니다. 바깥 경계는 차체 외곽 기준입니다. 경계 종료 UI는 `주행 경계 이탈`로 안내하되 엔진의 `collision` 코드·허용 영역·학습 기준은 변경하지 않습니다. `tests/boundary-and-background.spec.ts`가 네 방향 1mm 안/밖, 연석 위치, 실제 직진 종료, 배경 연속성·역방향 탐색·모션 감소·가독성을 검사합니다.

차고에서 고화질/성능 우선을 선택할 수 있습니다. 저해상도·그림자 변경은 엔진/센서 정확도를 바꾸지 않습니다. WebGL context loss는 실행 중단·재시도를 제공하며 CI는 전체 테스트를 3 shard로 검사합니다. [실행 방법과 검증 한계](../docs/web-stability.md)를 참고하세요.

## 하단 UX와 캐릭터 전시

- `MascotShowcase`는 생성된 브랜드 영상을 native video로 표시합니다. 기존 콘셉트 이미지의 캐릭터가 움직이는 연출이며 학습 정책 추론이 아니고 데이터도 저장/전송하지 않습니다. 실제 주행이 아니라는 표시를 유지합니다. 탑승 연출의 코드 기반 `MrParkRobot`은 별개입니다.
- 처음 화면에 보이고 모션을 허용할 때 영상을 요청합니다. 화면 밖/탭 숨김/전체 모션 중단/개별 일시정지에서는 재생을 멈춥니다. 동작 줄이기에서는 처음부터 영상 파일을 요청하지 않고 정적 포스터를 표시합니다. 로딩 실패는 콘셉트 이미지로 복구하며 자동재생 차단 시 재생 버튼을 제공합니다. 별도 캐릭터 WebGL Canvas나 외부 영상 스트리밍 서버가 필요하지 않습니다.
- 소개 구간의 `미스터팍 주행 보기`도 같은 맵과 첫 기록 선택을 거쳐 실제 정책을 시작합니다. 하단 빠른 이동은 차고 복귀만 제공합니다. 첫 화면과 떠 있는 메뉴의 모션 버튼은 제거하고, `화면 설정 · AI 모델 정보 → 화면 움직임 줄이기`로 모았습니다. 기기의 동작 줄이기를 우선하며 캐릭터 영상의 개별 재생/정지는 유지합니다.
- 기록 창은 서버 수집 불가 이유를 해당 선택지 안에 표시합니다. 아무 보관도 고르지 않은 경우 `기록 없이 시작`을 사용하며, 보관을 선택하면 저장 버튼을 활성화합니다. 기본 동의 상태나 서버 경계는 바꾸지 않습니다.
- 기술 전시의 휠 확대를 끄고 모바일 세로 터치를 허용해, 3D 위에서도 페이지를 내려볼 수 있습니다. 가로 드래그 회전과 조향 슬라이더는 유지합니다.
- `tests/landing-ux.spec.ts`는 영상 재생·정지·업로드 없음·관전 진입·390/1440px·3D 위 스크롤을 검사합니다. `tests/editorial.spec.ts`는 자체 글꼴·텍스트 진입·영상 실패/화면 밖 중단·오프닝 탐색을 검사합니다. 실제 모바일 GPU/터치 감각은 별도 실기기 검증 대상입니다.

## 글꼴과 텍스트 모션

Pretendard Variable v1.3.9를 자체 호스팅하며 [SIL OFL 고지](public/fonts/OFL.txt)를 포함합니다. 제목·본문·버튼의 한글/영문을 통일하고 계측 숫자는 tabular numerals를 사용합니다. 외부 폰트 CDN 요청은 없습니다. `font-display: swap`이므로 다운로드 전에도 시스템 글꼴로 읽을 수 있습니다.

`RevealText`의 제목은 줄 단위 마스크 안에서 850ms로 드러나며 줄 간격은 90ms입니다. 설명은 100ms 늦게 16px/700ms로 진입하고 다시 스크롤해도 반복하지 않습니다. 글자별 튀기·블러·스크롤 가로채기는 없습니다. 모션 중단/동작 줄이기에서는 모든 문장을 즉시 표시합니다. `editorial.css`에서 타이포그래피·최종 배경 강도를 관리합니다.

영상의 밝은 차체와 본문이 겹치지 않도록 **화면 왼쪽에서 오른쪽으로 이어지는 하나의 수평 그라데이션**으로 암부를 만듭니다. 글 주변에 둥근 음영·부분 매트·박스를 두지 않아 문장 길이나 섹션에 따라 얼룩이 생기지 않습니다. 제목은 밝은 백색, 본문은 밝은 청회색이며 글자 그림자는 2px로 제한합니다. 섹션은 계속 투명하고 모바일에서는 전체 영상 대비를 더 낮춥니다. 자동 테스트의 CSS/넘침 검사는 실제 화면의 시각적 검토를 대체하지 않습니다.

## 버튼과 시각적 위계

주요 시작 버튼은 불투명한 실버, 보조 메뉴/영상 제어는 짙은 스모크 글라스로 나눕니다. 유리 효과는 작은 보조 버튼에만 10px blur로 적용하고 미지원 브라우저에는 불투명 배경을 제공합니다. 주행 HUD는 배경이 변해도 읽을 수 있도록 거의 불투명하게 유지하며 기어·페달 입력 계약을 바꾸지 않습니다. 동의/거절 버튼에는 동일한 재질과 크기를 적용합니다.

포커스 링은 2px, 주요·영상·빠른 이동 버튼은 최소 44px 터치 영역을 제공합니다. 눌림은 140ms/0.985 scale이며 무한 반짝임·클릭 원형 파동은 없습니다. 동작 줄이기에서는 눌림/화살표 이동도 생략합니다. `tests/editorial.spec.ts`에서 390/1440px, 비활성 상태, 포커스, 동의 선택의 동등한 강조를 검사합니다.

시각적 참고: [Atmospheric Blade](https://threeui.com/backgrounds/matrix-field/atmospheric-blade)의 하나의 집중된 조명, [Matte Rise](https://threeui.com/text-animation/gallery-heading/rising-diagonal)의 차분한 제목 등장, [Dark Glass](https://threeui.com/buttons/rectangle-buttons/dark-pill)의 짙은 유리 재질. 참고 디자인의 코드·에셋을 복사하지 않고 서비스 구조에 맞춰 직접 구현했습니다.
