# 데이터·학습·평가 원칙

상태: 브라우저 로컬 기록·파일 검증·상태 재생은 [로컬 기록 안내](local-episodes.md), #11 초기 모델은 [학습 안내](../training/README.md), #12 웹 실시간 추론은 [마스코트 안내](mascot.md)에 구현되어 있습니다. 모델의 소규모 heldout 결과는 성공 0/1·충돌 1/1이며 일반화를 주장하지 않습니다. 실제 사용자 서버 수집·기여 데이터 재학습은 아직 하지 않습니다. 기여 동의/서버 저장 [#13](https://github.com/yumina0616/ai-championship-2026/issues/13), 지속 개선 [#17](https://github.com/yumina0616/ai-championship-2026/issues/17)을 구분합니다.

## 데이터는 무엇을 위한 것인가

사용자가 만든 환경 다양성과 관측/행동/실패 기록을 저속 주차 정책 연구에 활용하는 것이 목표입니다. 많은 시도가 곧 고품질 학습 데이터는 아닙니다. 실패 데이터도 분석에 가치가 있지만 잘못된 조작을 무조건 정답 행동으로 학습시키지 않습니다.

## 연습·공유·기여를 분리

| 동작 | 기본 | 서버 전송 |
| --- | --- | --- |
| 개인 연습/로컬 기록 | 가능 | 학습 목적 자동 업로드 없음 |
| 주차장 공유 | 사용자가 명시적 선택 | 공유에 필요한 맵만 |
| 주행 기록 기여 | 기본 해제 | 목적/범위에 동의한 Episode만 |
| 정책 모델 공개 | 검증 후 팀 선택 | 원시 사용자 식별정보 제외 |

기여를 거절해도 연습할 수 있어야 합니다. 회원가입·실주소·GPS·차량번호는 MVP 필수 항목이 아닙니다. 배포 인프라의 기본 접속 로그가 있을 수 있으므로 서비스 단계에서 실제 수집 범위를 확인합니다.

[#13](https://github.com/yumina0616/ai-championship-2026/issues/13)에서 보관 기간, 익명 기여 식별/삭제 방식, 동의 철회 후 원시 데이터와 미래 학습 스냅샷 처리, 이미 배포된 모델에서 즉시 학습 제거를 보장하지 못하는 한계를 구체화합니다. 이 결정을 하기 전에는 기여 업로드를 켜지 않습니다.

원시 기록/모델 가중치는 일반 Git에 올리지 않습니다. 안전한 소량 synthetic fixture만 커밋하고 큰 artifact는 접근 제어가 있는 저장소와 체크섬 manifest로 관리합니다.

## 저장할 것

[공통 계약](contracts.md)에 따라 맵 snapshot, 차종·엔진·센서·평가·정책 버전, seed, 관측, 요청/적용 행동, 다음 상태, 종료/실패, 사용자 도움·시점·개입, 동의 버전을 보존합니다.

브라우저가 보낸 success 플래그를 무조건 신뢰하지 않습니다. 학습 반영 전 서버/오프라인 검증으로 형식·일관성·필수 상태·상한을 검사합니다.

## 학습 누출과 관측 불일치

사용자는 탑뷰로 벽 뒤의 장애물을 볼 수 있지만 모델은 거리 센서만 받을 수 있습니다. 이때 사람 행동을 센서 관측만으로 설명하지 못하는 경우가 생깁니다.

- view_mode, 힌트, 전체 맵 표시, 수동 개입, 되감기 분기를 기록합니다.
- 기본 행동복제 데이터는 관측과 행동이 정렬되고 정책의 정보로 행동을 설명할 수 있는 범위를 선별합니다.
- truth를 사용하는 계획기 데이터도 출처를 명시하고, 정책 관측만으로 구분 불가능한 행동을 주입하지 않는지 검토합니다.
- 필요하면 관측 history/메모리를 도입하되 평가와 실제 추론에도 같은 정보를 줍니다.
- train/validation/heldout을 프레임 단위로 무작위 분리하지 않습니다. 같은 맵/trajectory가 여러 분할에 새지 않게 레이아웃군/seed를 나눕니다.
- 평가에 쓴 heldout에서 계속 모델을 선택했다면 그것은 validation 역할입니다. 최종 성능 주장에는 별도 잠근 test가 필요합니다.

## 초기 모델

유입 사용자 없이도 서비스가 작동해야 합니다. 팀원 기존 코드·허가된 데이터·기준 제어기 rollout으로 초기 모델을 학습합니다. 작은 행동복제 baseline은 출발안이며 기존 정책이 더 적합하면 근거를 남기고 재사용합니다.

학습에 필요한 것은 실제 observation→action을 학습한 artifact입니다. 계획기 실행이나 LLM 문구 생성만으로 이를 대체하지 않습니다.

Manifest 최소 정보: policy version, artifact checksum, framework/runtime 버전, 관측/행동 schema, 정규화, 지원 차량/센서/환경, data snapshot, train config/seed, 코드 commit, 라이선스, evaluation config와 전체 결과 위치.

## 평가 계획

초기 목표로 레이아웃군을 분리한 10개 이상 평가 맵과 맵별 3개 seed를 사용하되 비용/확률성에 따라 [#11](https://github.com/yumina0616/ai-championship-2026/issues/11)에서 실제 계획을 고정합니다. 결정론적 환경에서 seed만 바꾸고 같은 결과를 반복하는 것을 독립 표본으로 과장하지 않습니다. 이 수는 아직 실행 결과가 아닙니다.

비교 후보는 기준 제어기와 초기 학습 정책입니다. 후속에는 이전 정책과 새 기여 데이터로 학습한 후보를 같은 조건에서 비교합니다.

보고할 지표: 성공률, 충돌률, timeout/오류/개입률, 최종 위치·각도 오차, 시간, 이동 거리, 방향 전환 수. 분모·전체 실패·지원 범위 밖 사례를 표시합니다. 초기 작은 표본으로 통계적 일반화를 주장하지 않습니다.

사람과 모델은 정보/인터페이스가 다르므로 웹 비교 화면은 경험 비교이며 곧바로 알고리즘의 공정한 성능 벤치마크는 아닙니다.

## 참여로 성장하는 과정

동의한 기록 → 검증/정제 → 버전 있는 데이터 snapshot → 오프라인 학습 → 고정 평가 → 승격 또는 기존 정책 유지 → 서비스 버전 공개.

기여 횟수·기여 환경 수와 정책 평가 성적을 따로 표시합니다. 새 모델이 악화되면 배포하지 않습니다. 참여 시마다 경험치 애니메이션으로 실제 성능 향상을 주장하지 않습니다. 초기 제출에서는 이 지속 개선 주기 전체가 구현되었다고 적지 않습니다.

## 실제 차량과의 거리

본 데이터는 제한된 저속 모델·센서·조작 UI의 합성 데이터입니다. 센서 노이즈, 차체/타이어 차이, 지연, 사람 조작 장치 차이 등 현실과의 간극이 있습니다. 실차 적용은 다른 시뮬레이터 평가, 제어 한계 검증, 안전한 제한 실물 실험 등 별도 검증이 필요합니다.
