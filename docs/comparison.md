# 같은 환경의 시도 비교

구현: #14. 차고 → **내 주행 기록 → 비교에 추가**로 최대 2개를 고릅니다. 파일을 연 뒤 **열린 기록 비교에 추가**도 가능합니다. 최근 5개 목록에서 선택한 시도 전체를 보여주며 성공만 자동 선별하지 않습니다. 각 기록의 상태 재생은 기존 플레이어에서 따로 확인합니다.

- `engineVersion`, `scenarioVersion`, seed, 전체 Scenario snapshot(차량·센서·장애물·목표·평가·timeout), initial StepResult까지 일치해야 경로를 겹칩니다. 객체 key 순서는 무관하고 값은 정확히 대조합니다.
- 맵 이름만 같고 배치가 다르거나 초기 속도가 다르면 비교를 거부합니다. 개별 결과는 남기되 동일 조건 경로 그래프를 만들지 않습니다.
- 저장 step으로 footer를 다시 계산해 성공·충돌·종료 사유·완전성·시뮬레이션 시간·거리·실제 전후진 전환·위치/각도 오차를 표시합니다. 파일 입력 단계에서도 footer 일치 여부를 검증합니다.
- `user_abort`, `incomplete`, `engine_error`, `policy_error`, collision, timeout을 숨기지 않습니다. 기록에 충돌이 없다는 것이 앞으로 충돌하지 않는다는 의미는 아닙니다.
- A는 초록 실선, B는 주황 점선이며 좌표는 뒷차축 기준입니다. 모델 버전/체크섬, 주행 중 사용한 시점·도움의 합집합도 표시합니다. 연속 궤적만 보여주며 누락된 시뮬레이션을 만들어 채우지 않습니다.

사람은 탑뷰/주차 안내 같은 추가 정보를 볼 수 있고 모델은 거리 센서와 이상적 위치 기반 상대 목표를 받습니다. **경험 비교이지 동일 정보의 공정 벤치마크나 통계적 우월성 입증은 아닙니다.** 로컬 JSON도 암호학적 진위 증명은 아니며, 데이터셋/연구 성능 주장은 별도 검증이 필요합니다.

검증: `npm --prefix web test -- tests/compare.spec.ts`. 동일/상이 조건, 중단/추론 오류, 재계산 일치, 두 파일의 지표·경로 표시를 검사합니다.
