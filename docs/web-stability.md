# 웹 안정화와 PR 검증

## 그래픽 품질

차고의 그래픽 품질에서 **고화질**(기본) / **성능 우선**을 선택합니다. 선택은 `parkside-quality`에 저장하고 차단된 저장소에서는 이번 탭에만 적용합니다. 성능 우선은 pixel ratio 0.75와 그림자 비활성화를 사용합니다. 고화질은 ratio 1~1.25와 그림자를 사용합니다. UI 해상도와 장애물 형상, 물리 dt·성공 조건·센서 ray 수는 바꾸지 않습니다. 프레임 속도 향상 비율이나 실기기 FPS 수치는 아직 측정하지 않았습니다.

## 실행 중 오류

- WebGL 초기화 실패와 주행 중 context loss 모두 오류로 표시하고 엔진 입력을 중단합니다. 다시 시도는 새 Canvas를 만들어 초기화합니다.
- 리소스 진입 중 취소/timeout이 발생한 실행은 나중에 응답이 와도 시작하지 않습니다.
- blur/탭 숨김은 기존대로 일시정지합니다. 로컬 기록 재생도 탭 이탈이나 기록 패널 닫기 시 중단합니다.
- 저장 실패는 주행 성공처럼 숨기지 않고 파일 복구 안내를 제공합니다. 원격 저장소를 대신 사용하지 않습니다.
- 기록 체크포인트 교체에서는 과거 기록 본문을 읽지 않습니다. 새 실행 생성 시에만 최근 5개 보관 상한을 정리하며, 반복 저장의 불필요한 메모리 복사를 줄입니다.

## 테스트 실행

```bash
cd web
npm run build
npm test
# CI와 같은 성능 우선 설정으로 전체 테스트
PARKSIDE_TEST_LOW=1 npm test
```

CI는 3개의 독립 shard에서 각 1 worker로 **전체** Playwright 테스트를 분할합니다. `fullyParallel`은 분할 단위를 test로 만들기 위한 설정이며 각 runner의 동시 브라우저 worker는 1개입니다. 각 shard는 엔진 타입/65개 테스트·웹 빌드를 실행하고, 실패 trace/screenshot을 `web-check-results-<shard>`에 보관합니다. 설치/빌드/브라우저 시작까지 포함한 job 상한은 15분입니다. 같은 PR의 새 push는 이전 실행만 취소합니다.

CI에서는 공개된 성능 우선 옵션을 localStorage 초기 상태로 선택합니다. 엔진을 mock하거나 센서·충돌·기록 검사를 끄지 않습니다. 고화질 전환도 별도 테스트로 검사합니다. 같은 시험을 로컬에서 재현할 때 `CI=1` 대신 `PARKSIDE_TEST_LOW=1`을 쓰면 기존 로컬 dev server를 재사용할 수 있습니다.

Ubuntu CI는 Xvfb + Mesa llvmpipe에서 실제 Chromium을 실행합니다. headless SwiftShader에서 관측된 입력/렌더링 지연을 분리하기 위한 테스트 실행 환경이며 제품 코드·물리 dt·판정 조건은 바꾸지 않습니다. 드라이버 정보는 `glxinfo -B` 로그로 확인합니다. Linux 재현 명령은 [개발 규칙](development.md#브라우저-ci-실패를-다룰-때)을 따릅니다.

Trace의 연속 화면 캡처만 끄고 DOM·네트워크·소스 trace와 실패 screenshot은 유지합니다. 새 캡처는 OS별 임시 절대 경로 대신 `test.info().outputPath(...)`에 저장합니다. 기존 PR에 도입된 macOS 전용 캡처 경로도 이 방식으로 수정했습니다.

기존 10분 단일 job은 Ubuntu 소프트웨어 WebGL 상태에서 브라우저 구간이 시간 초과되어 취소됐습니다. 로컬 통과와 원격 CI 통과를 구별하며, 단순 timeout만으로 테스트를 삭제하거나 성공 처리하지 않습니다. 실제 CI 결과는 각 PR check를 확인합니다.

## 검증의 한계

자동 브라우저 검증은 Chromium 390/1440px와 소프트웨어 WebGL입니다. 실제 iPhone/Android/Safari·느린 모바일 네트워크·장시간 발열·GPU별 품질 검증을 대신하지 않습니다. Three.js chunk 크기 경고는 남아 있습니다. 공개 배포·실기기 확인은 여전히 #4/#15 후속 조건입니다.

## 웹 변경의 통합 기록

1. #26 편집기
2. #27 편집 맵 운전
3. #28 로컬 기록
4. #29 파일 공유·보관 선택
5. #30 웹 안정화

2026-09-16에 #26은 main으로, #27~#30은 각각 선행 feature 브랜치로 병합되었습니다. 따라서 PR의 Merged 표시와 달리 main에는 #26까지만 반영되어 있었습니다. `feature/4-main-integration`에서 전체 웹 변경을 모아 main 대상 통합 PR로 반영합니다. main의 #26 트리가 원래 #26 head와 동일함을 확인하고, 중복 squash 이력의 충돌은 후속 웹 변경을 보존해 해결했습니다.

이후 연쇄 PR은 선행 PR 병합 뒤 다음 PR의 base를 main으로 바꾸고 diff·최신 CI·main 반영을 확인합니다. 팀원 브랜치는 force push하지 않습니다. #4 공개 preview와 #13 서버 기여 업로드는 이 통합의 완료 범위가 아니며 계속 미완료로 둡니다.
