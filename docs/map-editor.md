# 주차장 편집기 v1

`#garage` → **나만의 주차장 만들기**에서 시작합니다. 탑뷰 드래그는 0.1 m 간격이고 숫자 입력은 위치·방향·치수를 조절합니다. 터치 드래그 외에 물체 선택 목록과 숫자 입력을 사용할 수 있습니다.

- 차량은 개발용 4.4 × 1.8 m, 축간거리 2.6 m 한 종입니다. 실제 차종·실제 지도를 구현하지 않았습니다.
- 공간은 16.4 × 10.4 m로 고정합니다. 벽·직사각형 기둥·주차 차량은 최대 24개입니다.
- 시작 차량, 목표 칸, 물체의 회전 사각형 전체를 경계 검사합니다. 목표 크기, 시작/목표/장애물 겹침, 장애물 중복 ID, 비유한 숫자·크기 상한을 검사합니다. 유효성은 경로 존재 보장이 아닙니다.
- 시작 위치 입력은 화면상 차체 중심입니다. 엔진에는 뒷차축 위치로 변환합니다. 목표 pose도 중심에서 같은 1.3 m 오프셋을 적용합니다.
- 편집기 기둥 템플릿은 목표 선·옆 차량과 겹치지 않도록 기존 주행 프리셋보다 바깥쪽 x=1.75 m에 배치합니다.

## 파일 계약

`parkside-map.v1` JSON은 version, name(1~60자), start, goal, obstacles를 담습니다. 최대 128 KB이며 파일을 열 때 필요한 필드만 새 객체에 복사합니다. 차량·엔진 dt·센서·성공 조건은 v1 구현 고정값입니다. 임의로 바꾼 엔진 옵션을 가져오지 않습니다. 맵 이름에 주소·개인정보를 넣지 마세요.

내보내기는 브라우저 다운로드만 사용합니다. 업로드/서버 저장/학습 동의가 아니며 자동 네트워크 전송이 없습니다. 페이지 새로고침 전 보관하려면 파일을 내려받으세요. 파일 오류는 기존 편집 내용을 지우지 않습니다. 템플릿 초기화는 확인을 받습니다.

맵 적용 후 시작하면 동일한 Scenario를 엔진·3D 장애물·센서·목표 판정에 전달합니다. 편집 UI는 주행 중 표시되지 않으며 적용 시 필드를 복사하고 엔진 reset도 snapshot을 복사합니다. 다시 시작해도 적용 맵은 유지되고 템플릿을 선택하면 기본 맵으로 돌아갑니다. 사용자 맵에서는 고정 프리셋 주차선과 오프닝 시연을 표시하지 않습니다.

학습 마스코트는 #12에서 같은 Scenario snapshot을 받도록 연결할 예정입니다. 따라서 #6의 두 모드 실행, #8의 공개 배포 검증 조건은 아직 미완료입니다. 기록·시점 도움 메타데이터는 #10에서 연결합니다.

검증: `cd web && npm test -- tests/maps.spec.ts`, `npm run build`.
